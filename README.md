# 家家健康 B2B 合伙人中心

Family Health Partner Center，支持 GitHub Pages 和本机服务两种运行方式。

## GitHub Pages 网页版

网站：https://familyhealthc.github.io/family-health-partners/

打开即可使用，无需启动本机程序。默认进入虚构数据的演示工作区；右上角切换「我的工作区」可以登记自己的客户和订单。
数据通过 SQLite WebAssembly 在浏览器中核算，保存在 IndexedDB；不会上传到 GitHub，也不会自动同步到其他设备。
在「备份与帮助」导出完整JSON备份后，可以在另一台设备恢复。清除浏览器网站数据前请备份。

当前默认规则为：卖家两阶段均要求有效SKU≥10；KA按总部计奖；买卖双方可叠加，同一人兼任双边时只计买方30%；第一笔达到金额门槛的已完成订单计奖；从达标/订单完成日期起冻结30天。规则页可以调整，历史权益保留原规则快照。

构建命令 `npm ci && npm run build`，发布目录为 `docs/`。
部署文件只包含程序与虚构演示种子，构建不会读取 `data/` 业务数据库。

## 本机服务版

## 启动

需要 Node.js 24 或以上，首次运行先执行 `npm ci`。

```sh
npm run dev
```

打开 http://127.0.0.1:4317 。Mac 也可双击 `启动合伙人中心.command`。
程序仅监听本机，不作为公网或多人系统部署。

## 已实现

- 合伙人新增、编辑、搜索、状态与业绩查看。
- 客户新增、编辑、归属登记和主体/门店＋角色去重。
- KA总部关联；总部计奖与独立门店计奖两种可配置口径。
- 订单、佣金凭据补录、退款登记；原始交易事实保留。
- 开发奖、卖家20%与买家30%佣金分润、差额冲减与规则快照。
- CSV模板下载、预览校验、原子导入、重复文件和冲突编号检查。
- 奖励台账导出、结算草稿、审核、取消和线下付款凭证登记。
- 持久化操作记录，演示与正式工作区使用独立SQLite文件。

## 体验顺序

初次打开为**演示工作区**，所有人物、机构、订单及规则均为虚构或演示假设。

1. 在合伙人管理查看档案及其客户。
2. 在订单与退款查看原订单、佣金和退款记录。
3. 点击核算奖励。重复操作不会重复增加权益。
4. 在结算管理生成草稿，查看明细并审核。体验后可取消。
5. 右上角切换正式工作区。正式库初始为空，规则未确认。

正式使用流程为：确认规则 → 新建合伙人 → 登记/导入客户 → 导入订单及退款 → 核算 → 核对 → 生成结算草稿 → 审核 → 线下付款后登记凭证。

## 导入约定

界面下载对应CSV模板。仅支持 UTF-8 CSV，暂不直接读取XLSX；Excel可另存为CSV。
每次最多5,000行、5MB。金额字段以人民币**元**填写，最多两位小数，内部以整数分保存。

客户字段：

| 字段 | 含义 |
| --- | --- |
| id | 源系统稳定客户编号 |
| name | 客户名称 |
| subjectId | 主体＋门店唯一标识，同角色不可重复 |
| role | `buyer` 或 `seller` |
| buyerType | `independent` 或 `ka` |
| kaGroupId | KA总部唯一标识，同一连锁的门店填写相同值；KA必填 |
| partnerId | 已建立档案的合伙人编号，可空 |
| registrationVerified | `true` / `false`，表示真实主体核验已完成 |
| qualificationApproved | `true` / `false`，表示资质通过 |
| publishedSkuCount | 已核验有效在售SKU数量 |
| kaStoreCount | 已核验KA门店数 |
| registeredAt | 奖励注册/建店条件实际达标日期，`YYYY-MM-DD` |
| note | 可选备注 |

订单字段：`id,buyerId,sellerId,goodsYuan,commissionYuan,commissionVerified,completedAt,status,category`。
`goodsYuan` 为订单完成时实付商品额，不含运费，退款通过独立退款记录导入。
`commissionYuan` 为原订单真实平台佣金，缺失时留空并将 `commissionVerified` 设为 `false`。
本版主要接收已完成订单，`status=completed`。`pending/cancelled` 可保存但不计奖；
本版尚未实现订单生命周期的连续状态同步，导入时宜使用最终已完成订单。

退款字段：`id,orderId,goodsYuan,commissionYuan,completedAt`。
仅导入已完成退款。`commissionYuan` 是该次退款的真实佣金冲减，不能由目标费率推算。

预览不会写入；整批有错误时全部不写入。同编号不同内容会报错，不能静默覆盖。
佣金缺失的订单可在订单页凭来源凭据补录；计奖之后不允许直接覆盖佣金。

## 核算与结算口径

- 首单采用第一笔**达到金额门槛的已完成订单**，按退款后的单笔净商品额判断，不累计多单。
- 卖家交易奖始终要求有效SKU≥10；建店100元是否受SKU约束，可配置。
- 双边分润、同一人兼任双边、KA计奖单位和冻结天数需要在规则页显式确认。
- 规则确认前不生成正式工作区权益；修改规则后，已产生权益的客户/订单继续使用原版本。
- 订单导入时保存买卖双方合伙人归属。客户有订单或奖励后，第一版锁定归属，不支持迁移。
- 同一KA总部开发归属冲突时生成待核对项，需人工处理。
- 结算冻结期可设置30–45天，从对应注册/建店达标或订单完成日期起算。
- 退款通过追加负向权益冲减，不删除原记录。已付款后的负数保留为下期抵扣。
- 结算单生成后发生退款，需取消未付款结算单，再生成净额结算单。
- 本版没有银行、微信、支付宝转账接口。登记付款仅保存已发生的线下付款凭证。
- 报表日期按America/Los_Angeles显示，订单/达标日期按导入的业务日期保存。

## 数据与备份

`data/demo.sqlite` 与 `data/workspace.sqlite` 独立保存，重启不丢失。
备份前停止程序，再复制整个 `data/` 目录；不要只复制正在运行的SQLite主文件。
不要将业务数据库提交到代码仓库或随代码分发。
